## 4. Implementation details

- `getUserProfile()` calls the existing authenticated client:
  `apiGet<ProfileResponse>('app-users/profile')` → `GET /api/mobile/v1/app-users/profile`.
- Only `name`, `phone` and `email` are modelled and displayed. The envelope's `success` flag and
  `data` object are validated before reconciliation.
- Values render immediately from `useAuth().user`; after a successful GET, backend values win. A key
  absent from the response keeps the cached value; an explicit `null` or empty string renders
  `Not provided`.
- The screen owns a simple app bar with a safe back action: `router.back()` when history exists,
  otherwise `router.replace('/profile')`.
- The Profile Hub row uses `testID="menu-edit-profile"` and targets `/profile/edit`. Because Expo's
  generated typed-route declaration has not been refreshed, that one `router.push` uses a narrow
  `as never` cast with an explanatory comment.

## 5. State handling matrix

| State | Behavior |
|---|---|
| Initial load | Activity indicator with `Checking your profile…`; cached values remain visible. |
| GET success | Name / Phone / Email reconciled from `data` and rendered read-only. |
| Missing optional value | `Not provided`. |
| Network / non-auth HTTP error | Cached values retained; safe message plus shared `ApiErrorRow` with Retry. |
| 401 | `Session expired` message plus Go back; no sign-out or redirect. |
| 403 | `Not authorized` message plus Go back; no sign-out or redirect. |
| Back navigation | `router.back()`, with `/profile` fallback when no history exists. |
