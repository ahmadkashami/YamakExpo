## 4. Implemented behavior

### Editable fields
- **Name** — `TextInput`, `keyboardType="default"`, initialized from the current profile data.
- **Phone** — `TextInput`, `keyboardType="phone-pad"`, initialized from the current profile data.
  No country-code parsing and no automatic number formatting.
- Both inputs use `maxLength={255}`, `autoCapitalize="none"`, `autoCorrect={false}`, and the existing
  bordered-input / inline-error styling used by login and register. `value` is always controlled by
  local state; typing only updates that state.
- **Email** — a read-only `Text` row bound to the loaded baseline. There is no `TextInput` for Email
  and no code path that can change it from this form. Missing values render `Not provided`.

### State management (three separate concerns)
- `initialValues: ProfileValues` — the loaded baseline, seeded from `valuesFromAuth(user)` before the
  first render, then updated by a successful GET. Also the source for the read-only Email row.
- `draft: EditableDraft` — the current editable `name`/`phone` strings shown in the inputs.
- `dirty` + `dirtyRef: DirtyFields` — per-field "user has edited" flags. The ref is updated
  synchronously in `markDirty` so it is authoritative even before React commits a re-render.

`getUserProfile()` still reconciles the GET response with the cached auth values: an absent key keeps
the cached value, while an explicit `null`/empty string becomes a genuinely missing optional value.
`applyLoadedValues()` updates `initialValues` unconditionally but applies the loaded string to a draft
field **only when `dirtyRef.current[field]` is false**. Therefore a late GET response cannot overwrite
a field the user has already edited. Retry increments `attempt`, re-runs the GET through the same
guard, and preserves both dirty flags and the current draft.

### Loading / error / navigation behavior preserved
- AuthProvider prefill is visible immediately; the loading row is non-blocking and the fields remain
  editable while a GET or retry is in flight.
- Network/other errors keep the cached values and show the existing `ApiErrorRow` with Retry.
- 401/403 show "Session expired" / "Not authorized" with a Go back button; no sign-out or redirect.
- Back button uses `router.canGoBack()` then falls back to `router.replace('/profile')`.
- The screen remains protected by the inherited `(app)` gate; the Profile Hub's single `Edit Profile`
  row is unchanged.

### Validation
- `maxLength={255}` on both inputs enforces the confirmed cap during typing.
- `getLengthError()` produces the inline `Maximum 255 characters` message (using the project's
  existing `FieldError` pattern) for an over-length value arriving from a loaded profile.
- Empty values remain valid because both backend fields are nullable. No phone-format validation.

## 6. Known limitations

- The draft is **local only** and is lost on back navigation or unmount; there is deliberately no
  Save/PATCH and no persistence.
- The length error can only be triggered by an over-length value from the loaded profile, since
  `maxLength` already caps typing. This is intentional: no new mandatory rule was invented.
- The proposed final Edit Profile design is not approved; this screen is functional-only and its
  visual polish (icons, hint text, Save affordance) is out of scope until a design decision.
- No runtime verification was authorized or performed, so keyboard behavior, IME edge cases and the
  late-response race are verified by source review only, not on a device.
